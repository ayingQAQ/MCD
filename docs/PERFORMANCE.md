# 星系性能与缓存

三维坐标、透视相机、曲面食物贴图、光照、深度遮挡和营养数据保持原有行为。优化集中在渲染、内存和重复计算。

## 渲染

- 按需申请动画帧。旋转惯性、相机飞行、大小过渡结束后停止；输入、纹理载入、筛选和窗口变化会重新唤醒。隐藏页面暂停，卸载取消帧与监听器。
- 按 Geometry 和 Material 合并 InstancedMesh，球体、轮廓、星环、同款插画共享批次。每个实例仍保留独立世界变换、尺寸和视锥剔除；拾取使用原球体的真实几何，不改变餐品 ID。
- 鼠标悬停拾取每帧最多一次；点击仍立即拾取。复用投影与碰撞计算的临时向量。
- 星团范围由 React 缓存；遮挡面板的 DOM 尺寸只在布局同步与窗口变化时读取。详细投影诊断最多约每 120ms 更新一次，运动结束补一次最终状态。
- 保留原有 DPR 上限（桌面 1.5、窄屏 1.25），不通过降低星球数量或改回二维来提速。

## 缓存与释放

- 食物插画的已解码源图使用 LRU 缓存，最多 32 项，按宽 × 高 × 4 估算的像素字节最多 8 MiB；按最近使用顺序淘汰。相同资源的并发请求合并；失败不缓存，允许重试。
- 缓存仅持有公开静态 SVG 的解码图像，不缓存 WebGLRenderer、场景、GPU 纹理、营养接口响应或用户数据。重新进入星系可以复用源图，但 GPU 纹理为新场景所有。
- 退出星系释放实例缓冲、纹理、材质、几何体、事件和 WebGL 上下文。缓存上限指保留的源图像素估算，不代表浏览器总内存；活跃场景另有自身 GPU 资源。
- 商品照片仍由浏览器静态文件缓存和原有懒加载处理，不预先解码全部 158 款照片，也不启用 Three.js 无上限的全局缓存。

## 验证

GitHub Actions 的 `performance.spec.ts` 检查静止后的动画回调、相机再次唤醒、全景绘制次数及跨页面的源图复用。单位测试检查 LRU 淘汰、并发合并、失败重试，以及实例变换、筛选、剔除和拾取。原有浏览器测试继续覆盖旋转、缩放、路线、筛选、深链和 GPU 释放。

可在 Actions 手动运行 `Validate McCosmos`，选择 `performance` 仅执行专项浏览器检查；日常 push 仍执行完整验证。软件 WebGL 的回归计数用于比较同一环境下的工作量，不作为用户设备的 FPS 承诺。

优化前基线：Actions [39745800563](https://github.com/ayingQAQ/McCosmos/actions/runs/39745800563)，静止 400ms 仍有 24 次动画回调，全景 521 次绘制提交。
