# Skill 验收方式

本项目把以下三个层次分开记录，不用一个层次代替另一个：

| 层次 | 如何验证 | 证据 |
| --- | --- | --- |
| 算法与参数契约 | search / compare / alternatives 的单元测试，覆盖缺失、0、重名、严格筛选、原始单位、无结果、无效参数及来源输入失败 | Actions 单测日志 |
| 独立可执行包 | 在系统临时目录安装生成的包，从另一个无项目依赖的目录使用纯 Node 执行七个固定场景；验证数值、限制与失败退出码 | `skill-acceptance` 产物中的 acceptance.json |
| Agent/客户端使用 | 在目标 Agent 客户端安装、发现或显式触发 `$mccosmos`，由自然语言生成参数，检查是否实际执行、正确解释来源和异常 | 需要记录实际客户端与对话，不能把固定命令场景当作此项已通过 |

## 可复现场景

1. “对比巨无霸和麦香鱼的营养差异。”应输出两个原始规格、逐指标原值与第二项减第一项的差异；未验证单位保持原值。
2. “找比巨无霸热量低、营养特征相近的同类替代品。”候选必须严格小于其热量，同类别，相似度达到声明阈值，不包括原餐品；说明类别是本地推断。
3. “早餐里不超过400 kcal的有哪些，按热量升序。”所有结果均满足上限，不把缺失值算0。
4. “冰牛奶有哪些具体杯型？”列出原始小、中、大杯，不让 Agent 随机挑规格。
5. 搜不到或筛选后为空时，说明没有符合项，不编造结果。
6. 指定外部文件失败时，非零退出且无默认快照回退。
7. 对比命令上误用筛选参数时，明确报错，不默默忽略用户条件。

额外来源测试使用模拟 MCP 响应夹具验证解析和获取时间保留，夹具不是官方真实菜单。本项目已有真实 MCP 同步证据，见 [MCP_INTEGRATION.md](../MCP_INTEGRATION.md)。CI 不访问个人 Token 或认证接口。

Skill 工作流支持可选的 workflow_dispatch 输入 skill_args（JSON 字符串数组），供独立 Agent 根据自然语言请求选择命令。它在远程临时目录复制并实际执行独立包，保存 skill-agent-invocation 产物；参数经数组校验后作为 argv 传入，不经过 shell。该试用只用包内快照，不接受外部文件或凭据，不等同于目标客户端自动发现 Skill 的验证。未实际调度运行前不能称为 Agent 试用通过。

## 下载与手动验收

从成功的 `Validate McCosmos Skill` 工作流下载 `mccosmos-skill`，将其中 mccosmos 文件夹放到客户端支持的 Skill 目录。Codex 用户可使用 `~/.agents/skills/mccosmos`；如果当前客户端会话尚未发现它，启动新会话再显式调用 `$mccosmos`。独立包运行示例：

```sh
node "/path/to/skills/mccosmos/scripts/mccosmos.mjs" compare --from="巨无霸" --to="麦香鱼"
```

要求最新数据的请求应由宿主 Agent 实际调用 MCP，再提供 --response 与该次 --fetched-at。MCP 不可用时必须说明，不能把包内快照说成刚刚查到的结果。网页、收藏、任务与实验台不参与离线分析，链接也不触发这些状态变化。
