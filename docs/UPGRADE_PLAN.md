# McCosmos 2.0 实施计划

> 需求：`McCosmos 2.0.md`；基线与取舍：`docs/UPGRADE_BASELINE.md`。按用户要求直接实施，main 提交、云端验证。

## 全局约束

真实数据共用一份 Repository；不改 MCP/TOON/营养标准化/图算法；不发起下单。默认官方快照，显式 demo 在所有页标识。未核实单位继续显示原始值。保留原创 SVG 系统与独立图库。localStorage 校验、限长、版本化、模式隔离；存储不可用不白屏。

## 阶段与接口

- [x] 1. 先提交比较、持久化、每日任务与五页端到端契约测试，Actions 确认 RED。
- [x] 2. `src/core/comparison.ts` 提供原值、单位一致性与首两项差值；`src/core/quests.ts` 生成确定有解的三类每日任务并严格验证；`src/state/persistence.ts` 负责容错存储。三个模块只依赖现有数据与图算法。
- [x] 3. `FoodProvider` 统一 dataset/graph/discoveries 与浏览器状态，`App` 提供五页导航、全局搜索与来源面板。React Router 支持深链、刷新、返回，离线 server 增加有限 SPA 路由回退。
- [x] 4. 独立星系保留现有 Canvas 与筛选发现；扩展关系命中、深链、上一站/下一站/播放/退出、收藏与实验室动作。共享档案与图鉴列表保证键盘可用。
- [x] 5. 图鉴搜索分类完整数据排序收藏；实验室两到三项添加/替换/交换/清空、独立营养量尺、差值/相似度、返回星图航线与 PNG 对照卡。
- [x] 6. 观测站提供有效入口、当日真实任务、最近查看、统计与稳定序列随机发现；任务页三种验证任务、线索、领取一次印章、本地保存、静音默认与分享成果。
- [x] 7. Actions 类型/Lint/单测/构建/全部 E2E；四档视口、错误/空/慢加载、深链与存储损坏验证，人工审阅截图。最终独立审阅、文档、线上部署。

## 验证重点

任务按本地日期和数据版本固定且候选有解；模式切换不可混淆来源和收藏；缺失不补零；3 项实验台满额提示；未知 ID 不崩溃；详情不遮挡底部导航；线上与离线服务器均支持五页刷新。复用 12 条任务书链路并保留原有营养/图/手势/插画测试。
